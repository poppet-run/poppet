# Phase 36: HTTP MCP servers

[Implementation plan](../implementation-plan.md) · [Documentation index](../README.md)

Implemented with automated checks. Let a configured MCP server be a remote
Streamable HTTP endpoint as well as a local stdio command, with static headers
drawn from environment or protected credential references. OAuth and the legacy
HTTP+SSE transport stay out of scope; a stdio bridge can front a server that
needs either.

### Implementation status

- Config: `MCPServer` is a union of `MCPStdioServer` (unchanged) and
  `MCPHTTPServer` (`url`, optional `headers`). Unknown fields are still errors,
  so an entry with both `command` and `url` is rejected. URLs must be `https:`, or
  `http:` to `localhost`, `127.0.0.1`, or `[::1]`, without userinfo or a fragment.
  Header references reuse `{ env }` / `{ credential }` with an optional `prefix`;
  transport-managed headers and case-insensitive duplicates are rejected.
- Transport: `ScopedHTTPTransport` wraps the SDK's
  `StreamableHTTPClientTransport` (already in the pinned 2.3.1 client, so no new
  dependency). Close is shared between the client and owner finalizer, sends the
  session `DELETE` within 5 seconds, then aborts open requests. The SDK's stream
  reconnection is off (`maxRetries: 0`), so the existing 30-second-to-10-minute
  backoff is the only retry path. Redirects use the SDK's `same-origin` policy.
- Bounds: `boundedFetch` caps a JSON body as a whole and an SSE stream per event
  at 256 KiB while the body streams, matching the stdio read buffer. A long-lived
  stream of small events is not cut off.
- Service: one connection lifecycle serves both transports. Resolved header
  values join the selected-secret set for redaction and definition checks.
  `status` adds `transport` and the endpoint `origin`; `pid` is null for HTTP.
  A transport error during startup now reports the startup diagnostic with its
  configuration hint instead of the generic disconnect message, for both
  transports.

Tests use an in-process `Bun.serve` fixture: JSON and SSE responses carrying
credential and environment headers in one session, redaction, the session
`DELETE` on close, oversized JSON bodies and SSE events, padding events that are
large together but not one by one, an off-origin redirect that never reaches the
other host, and a failed call that is reported uncertain, reconnects with a new
session after backoff, and is not replayed. Config tests cover accepted and
rejected URLs, managed and duplicate headers, literal header values, and mixed
stdio/HTTP fields. Existing stdio tests pass unchanged apart from the narrowed
fixture type.

Remaining manual checks: with one trusted remote server that accepts a bearer
token, store the token as a protected credential, reference it from
`headers.Authorization`, run `poppet mcp tools <id>` through the worker, and
complete a real-model tool round trip from the CLI. Confirm the server sees the
session end when the worker stops.
